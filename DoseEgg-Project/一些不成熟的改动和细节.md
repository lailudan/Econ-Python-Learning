# 目前状态:

大圆角 (rounded-[28px]) 与卡片流：这种设计语言在视觉上非常温和，减少了记录疾病时的心理压力。

状态点 (statusDot) 与标签系统：用颜色区隔 Med、Symptom、Meal、Activity，这不仅仅是为了好看，而是为了实现“秒级识别”。当病人处于 OFF 期边缘、脑雾（Brain Fog）严重时，这种色彩感知比阅读文字更高效。

“Bridge Dose”（桥接剂量）开关：这是一个天才的设计（自吹自擂）。它承认了药理节奏的非线性。只有病人才懂。

“Cognitive load may accelerate OFF”：在报告预览里加入“认知负荷”这一变量，这正是 HEOR（健康经济学与结果研究）的核心思维——关注生活质量（QoL）的变量，而不仅仅是生化指标。比如读书，写报告，做数学题也会根据每个人不同的情况消耗药效等。

我的DoseEgg的设计初衷就是通过记录掌握滴定和生活的主权，通过数据分析尝试最适合的用药时间和记录类似蛋白质竞争等数据优化自己的生活，并可以通过这些记录的数据分析记录更好的和医生沟通 - 患者主权。这也是2017年新的日内瓦公约提到的医生必须尊重的 autonamy “我将尊重病人的自主权（Autonomy）和尊严。”

Academic Entrepreneurship 、 Evidence-Based Entrepreneurship 循证创业
不是在为了融资而编故事，而是在为了解决一个“真实存在的学术缺口”而构建一个工具。在这种语境下，公司只是一个“研究载体”，而赚钱确实只是我们完成“价值对齐”后的副产品。

它到底是“记录工具”还是“预测工具”？我们测试后才知道。

# 数据层面的“进化”改动:

“Kick-in” 计时器：
在 Timeline 里，如果能自动计算 med 到下一个 symptom: good 之间的时间差（Lead Time），那这个 App 就能自动帮病人拟合出属于ta的药物起效曲线，SMC模型的可行性？
⚠️，这不是闹钟，原则上自我管理不设闹钟，N-of-1 trial的精神

蛋白质对比层：
目前的 Meal 只是一个标签。如果能让它与接下来的 Med 产生视觉上的关联（比如在 Timeline 上画一条虚线，显示蛋白质对吸收的截断效应），那“蛋白质效应”就会变得直观可见。

步数/或其他高消耗的活动（包括脑力）与多巴胺的“盈余/亏空”视图和因果关系：
既应该能显示一个“体能储备值”。高强度运动后，App 应该自动提醒：“当前多巴胺支出较高，建议补水/静止。”

睡眠数据、女性经期数据等可选择log - 不同onboarding版本的话感觉需要大量数据，而且病人很难定义自己是什么人
⚠️ 不用和apple health竞争 记录RBD（REM 睡眠行为障碍）等

代码逻辑与 Python 后端的桥接
DoseEggMockup 中，timeline 是一个非常标准的 JSON 数组。这简直是为 Python 的 pandas 数据帧（DataFrame）量身定做的。
药品目录也应该随时间和国家地区不同名字更新改进
